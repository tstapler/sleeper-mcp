## Concerns
- [ ] Story 1.2 Task 1 — `BrowserBackend` trait has no methods, no AC, and no defined relation to `BrowserSession` — Delete it from the v1 seam (one trait suffices for headed/headless + spike swap) or define its API now (e.g. transport-level `connect(endpoint)` owner vs session-level `goto`/`eval`); as written it is speculative generality that every later story must guess around.
- [ ] Stories 1.2/1.3 — Layer rule ("session never spawns processes, launch never evals JS", research §2) is stated but unenforced — Add grep-gates alongside the existing `rg chromiumoxide src/cli.rs` gate: `rg 'std::process|Command::|tokio::process' src/browser/session.rs src/browser/stealth.rs` must be empty, and `rg 'evaluate|eval_bool|eval_dump' src/browser/launch.rs src/browser/cft.rs` must be empty; or enforce via module privacy (`pub(crate)` constructors, process handles never leaving `launch.rs`).
- [ ] Story 1.3 Task 2 — WS-endpoint discovery mechanism unspecified (`--remote-debugging-port=0` yields an OS-chosen port) — State how `StealthLauncher::spawn` learns the endpoint (parse Chrome stderr `DevTools listening on ws://…`, vs fixed port + lockfile, vs `--remote-debugging-pipe`); AC1 ("connects within 10s") is unimplementable as written without this, and stderr-parsing vs fixed-port changes the orphan/lock design.
- [ ] Story 2.2 — Dependency inventory incomplete ("ADD zip only", plan line 106) — `setsid` + `SIGTERM→SIGKILL` needs `nix` (or `libc`), lockfile needs `fs2`/`fslock` (research §4 names them); add both to the dep line and to Story 2.2 Task 1/2 file lists, or the Epic 2 build plan fails on first compile.
- [ ] Tech Debt Disposition row 1 — "confines all chromiumoxide use to `src/browser/session.rs`" contradicts Story 1.3 Task 3 + row 2 (`Browser::connect` return type/`Browser::launch` ban imply `launch.rs` also touches chromiumoxide types) — Reword to name the true ownership (e.g. transport types owned by `launch.rs`, `Page` use confined to `session.rs`, zero imports in `cli.rs`), so the AC1 grep-gate matches the disposition.
- [ ] Story 2.1 — Pinned vs runtime Chrome versions compared as interchangeable strings (AC2: `145.0.0` vs `146.0.0`) — Introduce `PinnedVersion`/`RuntimeVersion` newtypes (or a single `CftVersion` + distinct params on the skew check) so the fail-fast comparison cannot silently swap its operands; pure helpers `cft_url`/`cft_path` should take the typed version.
- [ ] Stories 1.1/1.4 — Spike verdict not wired to Epic 1 gating — Story 1.4 parity runs assume 0.9.1 transport, while Tech Debt row 1 ("isolate via seam") is containment, not a fix, for WS-spam skew; add an explicit gate (if parity fails with WS/protocol errors, Story 1.1 verdict flips to adopt before Epic 2) and promote "if adopt, file follow-up task" to a concrete Story 1.1 Task 5 with owner/date, or the adopt path evaporates.
- [ ] Story 3.1 Task 3 — Flow-specific `goto_league`/`claim_player` trait methods violate ISP and contradict research §3 (generic `click_selector`/`wait_for_selector` + selectors in the flow module) — Extend the trait with small generic primitives only, keep claim/lineup/trade logic in flow modules; otherwise every new flow forces all impls (including fakes) to grow.

## Nitpicks
- Poll-timeout ownership is split: `LaunchConfig` "centralizes timeouts" (glossary) but `LoginPoll`/`wait_for_manual_login(timeout)` takes it as a param — pick one owner (recommend: launch owns spawn/connect timeouts, session/CLI owns poll timeout).
- Story 2.4 exit codes `0/1/2/3` as raw ints — use an `ExitCode`/`StatusVerdict` enum at the CLI boundary so skew vs lock-busy can't be confused at a call site.
- Glossary-to-story traceability: `StealthLayer`, `DebugDump`, `WaiverClaim` have no owning story/task; either link them or trim the glossary so reviewers can check every term is built somewhere.
