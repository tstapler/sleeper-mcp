## Concerns (carried over unchanged — partial mitigations noted, none fully closed by this patch)
- [ ] **Chaser-oxide spike (Story 1.1) is too thin to support an adopt verdict and has no sequenced follow-up.** One `cargo build` + one `status` run cannot detect WS-spam/stealth deltas (Epic 1's own gate demands ≥3 runs per state); AC1 permits `adopt` on build+license alone; commercial-orbit / bus-factor rejection criteria are undefined ("watch" with no tripwire); if the verdict is `adopt`, no migration story is sequenced (Epic 1 proceeds on 0.9.1 regardless). — Require ≥3-run stealth delta + explicit adopt/reject criteria (license, maintainer activity, commercial-orbit tripwire); file the migration story now, gated on the verdict.
- [ ] **Live-Chrome-dependent stories dominate with no hermetic seam test.** Stories 1.3/1.4/2.2/2.3/3.x gate on visible Chrome + live sleeper.com + a human operator; the only automated gates are `rg` greps. No fake `BrowserSession` for CLI tests, no fixture-based test for login-signal conjunction, lock contention, or triage lines. CI can enforce none of the ≥3-run gates. — Add a fake/mock `BrowserSession` + unit tests for signal conjunction, exit-code matrix, and triage-line contracts that run without Chrome.
- [ ] **No coherence checks across the signals detectors actually cross-reference.** `features.md §2` requires UA ≡ `Sec-CH-UA` hints ≡ `userAgentData`, permissions ≡ `Notification.permission`, plugins surviving iteration, `window.chrome` matching the pinned version. Plan tests `webdriver===false` + UA substring only. A coherent-UA/ incoherent-everything-else browser is *more* fingerprintable than stock. — Add a coherence assertion bundle (or explicit non-goals with justification) to Story 1.3/2.3.
- [ ] **Version diagnostics are quarantined in `doctor`/skew paths instead of on every run.** `features.md §4` requires startup printing Chrome version, driver/CDP-binding versions, patch fingerprint on every run; observability plan logs only mode + CfT version + profile path, and `--json` carries no versions — so the post-mortem for a silent re-detection has no data. CDP-binding version (the already-biting WS-spam skew) is never surfaced anywhere. — Log versions + effective flags + patch fingerprint on every launch; include them in `--json` and doctor alike.
- [ ] **Three canonical paths for the CfT cache.** `pitfalls.md` says `<data_dir>/stealth/`, Glossary says `<data_dir>/cft/<version>/`, Story 2.1 ACs say `cache/cft/`, Story 1.4 says `cache/chrome-profile` while `config.rs:43` owns `<data_dir>/chrome-profile`. `cache/` vs `data_dir` conflation breaks the "binaries/cache live elsewhere, never in the profile" invariant and makes backup/quota/cold-start behavior unpredictable. — Fix one canonical layout in the Glossary and update every AC/task to it.
- [ ] **Epic 4 CLI shapes are guessed, violating the plan's own never-guess rule.** `lineup set --slot/--player` and `trade propose --give/--get` are fully specified with no Q-gate equivalent to Q5, while requirements appetite says cut lineups/trades first on overrun and the cut rule ("if Epics 1–3 exceed week 4") names no measurable trigger. — Gate 4.1/4.2 on live-verified selector bundles like Q5, and define the cut trigger (date + which Epic is mid-flight + what "defer" leaves behind).
- [ ] **New UX contract (`--json`, exit 0/1/2/3, spinner, `doctor`) is untraced to requirements and `logged-out = exit 1` breaks scripts.** Requirements success metrics mention exit codes nowhere; `src/main.rs:21` already uses `exit(1)` for errors, so exit 1 now means both "error" and "logged out". No migration note for existing callers. — Trace each UX addition to a requirement or mark it discretionary; reconsider logged-out exit code (e.g. 0 + verdict, or distinct 10+) and document the contract once.
- [ ] **Fresh-profile procedure (Story 1.4 AC1) is incoherent and risks the warm signal.** "Wiping between runs 1–2 only" means runs 2–3 share state under a "fresh-profile" label; wiping as a fix for detection destroys exactly the persistence `pitfalls.md §3.3` says looks human. — Specify pristine-dir-per-run (or explicit warm-then-measure), forbid profile deletion as a detection fix, and separate fresh criteria (challenge solvable once, then persists) from authenticated criteria (zero challenges).
- [ ] **Claim failure coverage is one happy-path-adjacent case.** Story 3.2 AC2 tests only invalid-player; missing: network timeout mid-claim, DOM-changed mid-claim (stale selector after Q5 freeze), double-submit / already-claimed idempotency, claim-submitted-but-confirm-unseen. No per-step timeouts or idempotency key. — Extend the failure matrix before coding claim automation.
- [ ] **Timeout/retry budgets exist only for the 10-minute poll.** CfT download, `Browser::connect` (headless path unspecified; headed gets 10s), CDP evals, hydration wait, claim per-step — all unbounded. A hung headless `status` violates the "few seconds" SLO with no kill switch. — Assign a budget per I/O boundary in `LaunchConfig` and assert them in tests with fake clocks/timeouts.
- [ ] **Maintenance treadmill has no closed loop.** Per-release re-validation is a doc entry, not the CI probe + auto-filed update task `pitfalls.md` checklist #2 demands; verifiable chromiumoxide removal (`cargo tree | grep`, `pitfalls.md §2.4` feature-flag) has no implementing story despite the success metric "removed or isolated". `zip` also deepens the 3–5-minute codegen build with no caching note. — Add the CI probe story and the feature-flag/removal-verification story, or explicitly defer both with dates.
